# 02 — Backend Walkthrough

## Entry Point: `src/main.py`

Starts the FastAPI server using Uvicorn, reading host/port from `src/.env` (defaults `127.0.0.1:8000`).

```
python src/main.py
```

---

## Config: `src/config.py`

Central place for all paths and environment variables. **Every configurable value lives here — nothing is scattered across modules.**

| Variable | Default | Description |
|---|---|---|
| `APP_HOST` | `127.0.0.1` | Bind host (set to `0.0.0.0` to expose on network) |
| `APP_PORT` | `8000` | HTTP port |
| `TIME_WINDOW` | `60` (seconds) | Co-action time window for all coordination signals |
| `MIN_EDGE_WEIGHT` | `2` | Minimum co-actions to create a graph edge |
| `BOB_API_KEY` | `""` | IBM Bob API key (required for live classification) |
| `BOB_MAX_COST` | `0.25` | Max BOB coin spend per classification call |

Paths:
- `RUNS` → `data/runs/<dataset_id>/` — all analysis artifacts
- `SAMPLES` → `src/samples/` — committed demo data
- `BOB_RULES` → `.bob/rules-osint-analyst/` — legal table + prompt rules

---

## API Routes: `src/api/main.py`

### Startup (`lifespan`)
On first launch, if `data/runs/demo/` does not exist:
1. Copies `src/samples/demo_run/` to `data/runs/demo/` (fast, pre-analyzed)
2. If demo_run is absent, re-runs the full pipeline on `src/samples/scenario_posts.csv`

### Routes

| Method | Path | What it does |
|---|---|---|
| `GET` | `/api/status` | Returns `bob_configured` boolean and version |
| `GET` | `/api/datasets/demo` | Returns metadata for the demo dataset (post count, account count, analyzed flag) |
| `POST` | `/api/datasets` | Upload a CSV file → saves `posts.json`, returns dataset_id |
| `POST` | `/api/datasets/:id/analyze` | Run full Phase 1 pipeline on a dataset |
| `GET` | `/api/datasets/:id/graph` | Return `graph.json` (Cytoscape nodes/edges) |
| `GET` | `/api/datasets/:id/timeline` | Return `timeline.json` (60s activity buckets) |
| `GET` | `/api/datasets/:id/campaigns/:cid` | Return a campaign with its 10 sample posts |
| `POST` | `/api/datasets/:id/campaigns/:cid/classify` | Run IBM Bob Phase 2 classification |
| `GET` | `/api/datasets/:id/brief` | Generate and return the full HTML brief |
| `GET` | `/*` | Serve the React frontend from `src/web/dist/` |

## Engine Pipeline: `src/engine/pipeline.py` → `analyze()`

Orchestrates the full Phase 1 analysis. Called by the `/analyze` route.

**Steps:**
1. Save `posts.json` from normalized `Post` objects
2. Call `build_graph()` — multi-signal coordination network
3. Call `find_campaigns()` — Louvain clustering + scoring
4. Save `campaigns.json`
5. Build and save `graph.json` (Cytoscape format: `{nodes, edges}`)
6. Build and save `timeline.json` (60-second activity buckets with per-campaign counts)

**Returns:** `{dataset_id, posts, accounts, runtime_ms, campaigns[]}`

---

## Coordination Graph: `src/engine/coordination.py` → `build_graph()`

Wraps the QUT `coordination_network_toolkit`.

1. Formats posts into toolkit rows `(post_id, account_id, username, repost_of, reply_to, text, created_at, urls)`
2. Calls `preprocess.preprocess_data()` — stores posts in a SQLite `.db` file
3. Runs 5 network computations: `co_tweet`, `co_similar_tweet`, `co_link`, `co_reply` (300s window), `co_retweet`
4. Loads each sub-graph with `graph.load_networkx_graph()` and merges into one `nx.Graph`
5. When merging: edge weights are additive, signals are collected into a set per edge
6. Returns a single merged `nx.Graph` with `weight` and `signals` on every edge

---

## Campaign Detection: `src/engine/campaigns.py` → `find_campaigns()`

1. Runs `nx.community.louvain_communities(G, weight="weight", seed=42)` (deterministic)
2. Filters communities with fewer than `min_size=5` members
3. For each surviving community: extracts post IDs, top hashtag, inter-signal set, median account age
4. Calls `score_campaign()` to get a 0–100 risk score with per-feature breakdown
5. Sorts all campaigns by score descending, assigns sequential IDs `c1, c2, c3...`

---

## CIB Scoring: `src/engine/scoring.py` → `score_campaign()`

Computes a weighted integer score (max 100). Each feature contributes `round(100 × weight × value)` points:

```python
WEIGHTS = {
    "speed":         0.25,   # max 25 pts
    "duplication":   0.25,   # max 25 pts
    "multi_signal":  0.15,   # max 15 pts
    "fresh_accounts":0.15,   # max 15 pts
    "burst":         0.10,   # max 10 pts
    "concentration": 0.10,   # max 10 pts
}
```

All feature values are 0.0–1.0 before multiplication. The function returns `(total_score, features_dict)` where `features_dict` maps each key to its integer contribution.

## Post Loading: `src/engine/normalize.py` → `load_posts()`

Auto-detects file format from CSV header:
- **Standard scenario CSV** — `post_id, account_id, username, ...` (generated by `scenario/generate_scenario.py`)
- **X/Twitter IO Archive** — `tweetid, tweet_text, ...` (Information Operations Archive)
- **IRA Troll Archive** — `tweet_id, author, publish_date, ...` (FiveThirtyEight dataset)
- **JSON** — array of `Post`-compatible objects

---

## Bob Client: `src/bob/client.py` → `classify()`

1. Checks disk cache at `data/runs/<id>/bob/<cid>.json` — returns immediately if present
2. Builds classification prompt via `build_classification_prompt()` — injects campaign evidence, sample posts, allowed legal IDs from the legal table, and all rules from `.bob/rules-osint-analyst/*.md`
3. Calls `run_bob()` — spawns `bob run --format json --max-turns 2 --max-cost <X> --disable-mcp --disable-subagents`
4. Parses the JSON response from stdout, extracts `last_message` and `stats.session_costs`
5. Filters legal suggestions to only IDs present in the legal table with `kind=offence`
6. Falls back to a heuristic verdict if Bob parsing fails after 2 retries
7. Saves the verified `BobVerdict` to disk cache for zero-cost re-retrieval

---

## Escalation Engine: `src/engine/escalation.py` → `escalate()`

Deterministic rules — no AI involved:

| Condition | Level |
|---|---|
| `incitement` + offline CTA, **OR** score ≥ 80 AND severity ≥ 4 | **URGENT** |
| `organized_misinformation` or `targeted_harassment` AND score ≥ 60 | **ALERT** |
| Everything else | **MONITOR** |

---

## Brief Renderer: `src/brief/render.py` → `render_brief()`

Generates a self-contained HTML file suitable for printing/PDF:
- Computes SHA-256 of `posts.json` for tamper-evident provenance (BSA Section 63)
- Calls `generate_executive_summary()` — uses Bob if API key present, falls back to deterministic text
- Builds per-campaign cards with: feature breakdown, threat verdict, legal badges, action directives, evidence table (post ID, timestamp IST, handle, text, SHA-256 hash per post)
- Saves to `data/runs/<id>/brief.html` and also returns it as the HTTP response

---

## Legal Table: `src/bob/legal.py` → `load_legal_table()`

Parses `.bob/rules-osint-analyst/01-legal-table.md` — a Markdown table with columns:
`| ID | Law | IPC | Covers | Kind |`

`kind` is either `offence` (can be suggested to Bob) or `procedural` (for brief references only, never suggested as a penal charge). This prevents Bob from suggesting IPC sections that were struck down or are not valid under BNS 2023.

## Data Storage Layout

```
data/runs/<dataset_id>/
├── posts.json          Normalized array of Post objects
├── campaigns.json      Array of Campaign objects (from analysis)
├── graph.json          {nodes, edges} for Cytoscape.js
├── timeline.json       {bucket_seconds, campaign_ids, points[]}
├── brief.html          Generated HTML escalation brief
├── toolkit.db          Temporary SQLite (overwritten each run)
└── bob/
    ├── c1.json         Cached BobVerdict for campaign c1
    ├── c2.json         Cached BobVerdict for campaign c2
    └── summary.json    Cached executive summary from Bob
```
